Accueil et vérification

⏱️ 20 minutes

1.1 — Accueil

💬
Ce que dit le formateur

« Bienvenue ! Aujourd'hui, objectif concret : à la fin de la séance, chacun d'entre vous aura sa page web en ligne, accessible par un lien public. On va installer et comprendre 3 outils : VS Code (pour écrire le code), Git (pour garder l'historique), GitHub (pour publier en ligne). On commence par vérifier que tout est installé. »

1.2 — Vérifier Git

Ouvrir le terminal : Menu Démarrer → taper « Git Bash » → Entrée. Puis taper :

bash 
git --version

Résultat attendu : git version 2.xx.x.windows.x

🚫
Si « git n'est pas reconnu »
  • Git n'est pas installé → réinstaller
  • Redémarrer VS Code / le terminal après installation
  • Réinstaller en cochant « Git from the command line and also from 3rd-party software »

1.3 — Vérifier VS Code

Ouvrir VS Code → Fichier → Ouvrir le dossier → créer un dossier mon-site sur le Bureau et l'ouvrir.

Vérifier que tout le monde voit le dossier vide dans la barre latérale gauche.

1.4 — Vérifier GitHub

Ouvrir le navigateur → github.com → se connecter. Si la page d'accueil GitHub s'affiche, c'est bon.

⚠️
Point de vigilance

Certains n'ont pas validé leur email → le compte ne fonctionne pas pour push. Vérifier la boîte mail.

1.5 — Tour de table rapide

Dans le chat : ✅ si les 3 sont OK, ❌ + le problème sinon.

Traiter les ❌ un par un, ou proposer un suivi après le live sur le groupe Facebook pour ne pas bloquer tout le monde.

2

VS Code + extensions

⏱️ 25 minutes

2.1 — Configurer le terminal par défaut en Git Bash

Pourquoi : PowerShell affiche des messages Git moins lisibles et certaines commandes diffèrent. Git Bash est plus proche des tutos en ligne.

  1. Ctrl + Shift + P → taper « Terminal: Select Default Profile »
  2. Choisir Git Bash
  3. Ouvrir le terminal intégré : Ctrl + ù
  4. Vérifier que le prompt ressemble à user@machine MINGW64 ~/Desktop/mon-site

2.2 — Installer les 4 extensions

Cliquer sur l'icône Extensions à gauche (4 carrés) ou Ctrl+Shift+X.

Extension Nom exact À quoi ça sert
Live Server Live Server (Ritwick Dey) Recharge automatiquement la page dans le navigateur à chaque sauvegarde.
Prettier Prettier - Code formatter Formate automatiquement le code : indentation, espaces.
French Pack French Language Pack for Visual Studio Code Traduit l'interface de VS Code en français.
Material Icon Theme Material Icon Theme Ajoute des icônes à côté des fichiers.
💡
Activer Prettier à la sauvegarde
  1. Ctrl + , (paramètres)
  2. Chercher « format on save »
  3. Cocher Editor: Format On Save
  4. Chercher « default formatter » → choisir Prettier - Code formatter

2.3 — Créer et tester index.html

  1. Clic droit dans la barre latérale → Nouveau fichier → nommer index.html
  2. Taper ! puis Tab → VS Code génère la structure HTML (Emmet)
  3. Modifier le <title> et le <body>
html 
<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="UTF-8">
  <title>Ma première page</title>
</head>
<body>
  <h1>Bonjour, je m'appelle [ton prénom]</h1>
  <p>Ceci est ma première page publiée avec GitHub Pages.</p>
</body>
</html>
  1. Ctrl + S pour sauvegarder
  2. Clic droit sur index.html → Open with Live Server
  3. Le navigateur s'ouvre sur http://127.0.0.1:5500/index.html
✨
Effet « waouh »

Changer le <h1>, sauvegarder (Ctrl+S), constater que la page se met à jour toute seule.

3

Git en local, le cœur

⏱️ 35 minutes

3.1 — La métaphore Git / GitHub

💬
Ce que dit le formateur

« Avant de taper des commandes, une image. Git, c'est un appareil photo avec un album, sur votre ordinateur. À chaque fois que vous faites un commit, vous prenez une photo de votre projet. L'album garde toutes les photos, dans l'ordre. Vous pouvez revenir à une ancienne photo si vous cassez quelque chose. GitHub, c'est le cloud où vous rangez et partagez cet album. Git fonctionne sans GitHub. GitHub a besoin de Git. Ce ne sont pas la même chose. »

📸

Git

L'appareil photo + l'album sur votre ordinateur. Prend des photos (commits) et garde l'historique.

☁️

GitHub

Le cloud où vous rangez et partagez votre album. Nécessite Git pour fonctionner.

3.2 — Configurer son identité Git

Dans le terminal intégré (Git Bash) :

bash 
git config --global user.name "Ton Prénom"
git config --global user.email "ton.email@exemple.com"

Ces infos apparaîtront dans l'historique de chaque commit. Utilisez l'email de votre compte GitHub.

3.3 — Initialiser le dépôt

bash 
git init

Git commence à surveiller ce dossier. Il a créé un dossier caché .git qui contient tout l'historique. Ne le touchez jamais à la main.

bash 
git status

Résultat attendu : index.html apparaît en rouge dans « Untracked files ». Rouge = Git voit le fichier mais ne le suit pas encore.

3.4 — Premier add + commit

bash 
git add index.html
git status

Maintenant il est en vert dans « Changes to be committed ». C'est la salle d'attente avant la photo.

bash 
git commit -m "Première version de ma page"

Photo prise. Git a enregistré une version de votre projet avec un message.

bash 
git log --oneline

Résultat attendu : une ligne avec un hash court et le message.

3.5 — Deuxième modification + commit

Modifier le <h1> dans VS Code, sauvegarder, puis :

bash 
git status
git add index.html
git commit -m "Changement du titre"
git log --oneline

Résultat attendu : deux lignes dans le log. Vous avez maintenant deux photos de votre projet.

3.6 — Récapitulatif des 3 commandes

💡
Retenez ces 3 commandes (95% du temps)
  • git status → où j'en suis ?
  • git add fichier → je prépare la photo
  • git commit -m "message" → je prends la photo
4

GitHub + GitHub Pages

⏱️ 30 minutes

4.1 — Créer le dépôt sur GitHub

  1. Sur github.com, cliquer sur + en haut à droite → New repository
  2. Repository name : mon-site
  3. Public (obligatoire pour GitHub Pages gratuit)
  4. NE PAS cocher « Add a README file »
  5. Cliquer sur Create repository

4.2 — Connecter le dépôt local à GitHub

Copier l'URL du dépôt (bouton vert Code → HTTPS → copier).

bash 
git remote add origin https://github.com/TON_USERNAME/mon-site.git
git branch -M main
git push -u origin main
⚠️
Point de vigilance n°1 — l'authentification

Git Credential Manager (installé avec Git for Windows) ouvre une fenêtre navigateur → se connecter normalement. C'est le cas le plus courant en 2025.

Si ça demande un mot de passe en ligne de commande et que ça échoue : GitHub n'accepte plus les mots de passe classiques. Il faut un Personal Access Token.

Filet de sécurité : GitHub Desktop pour publier en 2 clics.

Rafraîchir la page GitHub → index.html apparaît dans le dépôt.

4.3 — Publier avec GitHub Pages

  1. Dans le dépôt, onglet Settings
  2. Menu de gauche → Pages
  3. Source : Deploy from a branch
  4. Branch : main, dossier / (root) → Save
  5. Attendre 1 à 2 minutes, rafraîchir → l'URL apparaît : https://TON_USERNAME.github.io/mon-site/
⏳
Point de vigilance n°2 — la latence

GitHub Pages peut mettre jusqu'à 10 minutes à publier la première fois. Ce n'est pas un bug. Pendant ce temps, on fait le quiz.

🚫
Si la page affiche une erreur 404

Vérifier que le fichier s'appelle bien exactement index.html (minuscules, bonne extension), et que la branche est bien main.

4.4 — Validation en direct

Dans le chat : coller votre lien GitHub Pages dès qu'il fonctionne. Le formateur vérifie en direct, valide, encourage.

5

Quiz et prochaines étapes

⏱️ 10 minutes

5.1 — Quiz

Q1. Git et GitHub, c'est pareil ?

Réponse : Non. Git = local, GitHub = cloud.

Q2. Quelle commande prépare un fichier avant le commit ?

Réponse : git add

Q3. Quelle commande enregistre une version ?

Réponse : git commit -m "message"

Q4. Où configure-t-on GitHub Pages ?

Réponse : Settings → Pages

Q5. Quel nom de fichier est obligatoire pour la page d'accueil ?

Réponse : index.html

5.2 — Devoir pour la prochaine fois

  1. Modifier index.html (ajouter une image, un paragraphe, changer les couleurs)
  2. Refaire : git add index.html, git commit -m "Mes modifications", git push
  3. Attendre 1-2 minutes, recharger le lien GitHub Pages : les modifications doivent apparaître.
✅
Le cycle complet à retenir

modifier → add → commit → push

5.3 — Où poser les questions

Le groupe Facebook reste ouvert pour vos questions. Collez-y vos messages d'erreur (copier-coller du terminal, pas de capture d'écran floue). Réponse sous 24-48h.

Prochaine séance : HTML/CSS, et on utilisera Git dès le premier jour.

Points de vigilance

À garder sous les yeux pendant toute la formation.

1

git push = moment de blocage n°1

Prévoir GitHub Desktop en secours. Ne laisser personne quitter sans son lien.

2

GitHub Pages peut mettre jusqu'à 10 min

Occuper ce temps avec le quiz, pas avec des rafraîchissements collectifs.

3

index.html doit s'appeler exactement comme ça

C'est la cause n°1 des erreurs 404 sur GitHub Pages.

4

Terminal = Git Bash, pas PowerShell

Configurer le terminal par défaut dès le début de la séance.

5

Ne pas cocher « Add a README » à la création du dépôt

Sinon conflit au premier push (erreur rejected).
